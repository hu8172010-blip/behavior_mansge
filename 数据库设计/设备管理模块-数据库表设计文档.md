# 设备管理模块 - 数据库表设计文档

> 模块：设备管理  
> 业务范围：跨摄像头异常行为轨迹分析系统 - 设备管理  
> 文档日期：2026-07-28  
> 数据库：MySQL 8.0+  
> 字符集：utf8mb4  
> 存储引擎：InnoDB  

---

## 一、表关系概览

本模块共包含 2 张核心业务表，关系为 **一对多**：

```
device（设备表）  1 ──── N  fault_record（故障记录表）
```

- 一台设备可以产生多条故障记录
- `fault_record.device_id` 关联 `device.id`
- `fault_record` 中冗余存储 `device_code`，避免高频查询时 join 设备表

## 四、设计说明

### 1. 主键策略

两张表均使用 `id`（BIGINT UNSIGNED 自增）作为物理主键。业务层面使用 `device_code` 作为设备的唯一标识，并建立唯一索引。

### 2. 外键关系

`fault_record.device_id` 关联 `device.id`，为多对一关系。考虑到高并发场景下的写入性能，可选择不在数据库层面建物理外键，仅由应用层保证数据一致性。

### 3. 冗余字段

`fault_record` 表中冗余存储了 `device_code` 字段，目的是避免每次查询故障列表时都需要 join 设备表，提升查询效率。需在设备标号变更时同步更新。

### 4. 逻辑删除

所有表均使用 `is_deleted` 字段做软删除（0 未删除 / 1 已删除），不进行物理删除，便于数据追溯和恢复。

### 5. 索引建议

| 表名 | 索引字段 | 用途 |
|:---|:---|:---|
| device | `device_code`（唯一） | 按标号查询设备 |
| device | `status` | 按状态筛选设备列表 |
| device | `region_code` | 按区域筛选设备 |
| device | `last_heartbeat_time` | 心跳超时检测 |
| fault_record | `device_id` | 查询某设备的故障记录 |
| fault_record | `device_code` | 按标号查询故障 |
| fault_record | `fault_type` | 按故障类型统计 |
| fault_record | `disposal_status` | 按处置状态筛选 |
| fault_record | `occurrence_time` | 按时间范围查询 |

### 6. 时间字段约定

- `create_time`：记录创建时间，默认 `CURRENT_TIMESTAMP`
- `update_time`：记录更新时间，`ON UPDATE CURRENT_TIMESTAMP` 自动更新
- 所有业务时间字段（如 `occurrence_time`、`recovery_time`）均存储为 `DATETIME` 类型，不带时区，统一使用服务器时区（Asia/Shanghai）
