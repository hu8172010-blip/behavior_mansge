# 人员跨摄像头轨迹数据库设计文档
## 基础说明
1. 共两张业务表：`track_pass_chain`（通行链路主表）、`track_pass_item`（途经摄像头明细表）
2. 关联关系：**一对多** `track_pass_chain.id = track_pass_item.chain_id`
3. 人员特征不再冗余存储，通过 `person_id` 关联【异常行为人员档案表】读取特征JSON
4. `device_route` 格式：`摄像头ID-摄像头ID`，示例：`1001`、`1001-1002`、`1001-1003-1002`
5. 时长单位：秒
6. 状态定义：1=行进中，2=已归档完成

## 表1：track_pass_chain 人员通行链路主表

| ---- | ---- | ---- | ---- | ---- | ---- |
| id | 链路主键ID | BIGINT UNSIGNED | 无符号大整数 | 主键、自增 | 整条轨迹链路唯一主键 |
| chain_unique_id | 链路唯一编号 | VARCHAR(64) | 变长字符串 | 唯一索引 | 前端页面、详情弹窗唯一传参标识 |

| device_route | 摄像头路径串 | VARCHAR(256) | 变长字符串 | 非空 | 按行走顺序拼接摄像头device_id，分隔符`-`；示例：`1001`、`1001-1002`、`1001-1003-1002` |

| last_device_id | 末尾摄像头ID | BIGINT UNSIGNED | 无符号大整数 | 非空 | 整条轨迹最后出现的摄像头设备ID；单摄像头场景与首个ID相等 |
| chain_start_time | 链路起始时间 | DATETIME(3) | 日期时间（毫秒精度） | 普通索引、非空 | 人员第一次被摄像头抓拍的时间 |
| chain_end_time | 链路结束时间 | DATETIME(3) | 日期时间（毫秒精度） | 可空 | 人员完全离开所有摄像头，轨迹结束才赋值；行进中为NULL |
| total_duration_sec | 全程总时长(秒) | INT | 整数 | 默认0 | 整条轨迹总耗时，单位秒 |
| chain_status | 链路状态 | TINYINT | 微整数 | 普通索引、非空，默认1 | 1=行进中，2=轨迹归档完成 |
| create_time | 记录创建时间 | DATETIME | 日期时间（秒级） | 非空，默认当前时间 | 本条链路初次入库时间，永久不变 |
| update_time | 记录更新时间 | DATETIME | 日期时间（秒级） | 非空，自动更新 | 链路任意字段修改时自动刷新，代表最后一次变更时间 |

## 表2：track_pass_item 途经摄像头明细子表
| 字段名称 | 中文名称 | 数据类型 | 数据类型中文 | 约束/备注 | 字段说明 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| id | 明细主键ID | BIGINT UNSIGNED | 无符号大整数 | 主键、自增 | 单摄像头分段记录唯一ID |
| chain_id | 所属链路ID | BIGINT UNSIGNED | 无符号大整数 | 联合索引(chain_id,sort)、非空 | 关联主表track_pass_chain.id，归属对应轨迹链路 |
| device_id | 当前摄像头ID | BIGINT UNSIGNED | 无符号大整数 | 联合索引(device_id,appear_time)、非空 | 该分段对应的摄像头设备编号 |

| create_time | 明细创建时间 | DATETIME | 日期时间（秒级） | 非空，默认当前时间 | 本条分段记录入库时间 |

# 关联关系汇总
1. `track_pass_chain.id`  ↔ `track_pass_item.chain_id`
   一对多：一条轨迹链路，对应多条摄像头途经明细
2. `track_pass_chain.person_id` ↔ 异常行为人员档案表.id
   一对一：通过该关联读取人员特征JSON，轨迹表不再冗余存储特征

# 状态规则 chain_status
- **1 行进中**
  轨迹未闭合，后续有可能捕捉到该人员出现在其他摄像头；允许新增track_pass_item明细，device_route可以持续追加摄像头ID；`chain_end_time` 为空。
- **2 已归档完成**
  触发条件：所有明细disappear_time全部赋值 + 距离最后一次update_time超过超时阈值（例如5分钟）；轨迹永久闭合，不再新增任何明细，属于历史轨迹。

# update_time 业务作用
1. 数据库自动更新：主表任意字段变更，自动刷新时间；
2. 前端实时列表按`update_time`倒序，最新轨迹置顶；
3. 定时任务依靠`update_time`判断超时，执行轨迹归档；
4. 用于数据变更追溯、缓存有效性判断。

# 完整业务情景演示
## 情景1：人员仅在摄像头1001出现，随后离开，无其他摄像头捕捉
1. 14:00:00 AI识别人员出现在1001
   - 新增 `track_pass_chain`
     device_route=`1001`，first_device_id=1001，last_device_id=1001，chain_status=1，create_time=14:00:00，update_time=14:00:00
   - 新增 `track_pass_item`，chain_id=主表id，device_id=1001，sort=1，appear_time赋值，disappear_time=null
2. 14:02:00 人员离开摄像头
   - 更新明细：填充disappear_time、stay_duration_sec
   - 更新主表，update_time刷新为14:02:00
3. 14:07:00 定时任务检测：全部明细已离开，距离update_time超过5分钟
   - 更新主表：chain_end_time赋值、total_duration_sec计算、chain_status=2
   - update_time刷新为14:07:00
> 最终路径字符串：`1001`

## 情景2：顺向行走 1001 → 1002 → 1003
1. 14:10:00 首次识别1001，主表route=`1001`，sort=1；update_time=14:10:00
2. 14:12:30 识别到1002
   新增明细sort=2；更新主表device_route=`1001-1002`，last_device_id=1002；update_time刷新
3. 14:15:10 识别到1003
   新增明细sort=3；更新主表device_route=`1001-1002-1003`；update_time刷新
4. 14:18:00 人员离开1003，更新明细离开时间
5. 14:23:00 超时触发归档，chain_status=2
> 最终路径字符串：`1001-1002-1003`

## 情景3：折返行走 1001 → 1003 → 1002
1. 识别1001 → route=`1001` sort=1
2. 识别1003 → route=`1001-1003` sort=2
3. 折返识别1002 → route=`1001-1003-1002` sort=3
4. 人员离开最后一台摄像头，等待超时后归档
> 最终路径字符串：`1001-1003-1002`

# 数据更新统一规则
1. 每新增一条track_pass_item，将device_id追加到主表device_route；
2. first_device_id = 路径字符串第一段设备ID；
3. last_device_id = 路径字符串最后一段设备ID；
4. 轨迹归档后，路径字符串不再变更；
5. 查询人员特征时，LEFT JOIN 异常行为人员档案表，通过person_id获取。
