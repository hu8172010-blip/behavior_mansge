# 权限管理系统数据库设计文档
## 一、文档概述
本文档为后台权限管理系统数据库设计，支持角色权限配置、账号独立自定义权限；采用物理删除，无逻辑删除标识`del_flag`；超级管理员为预置角色数据，无额外区分字段；权限规则：**账号独立权限优先覆盖角色权限**。

### 数据表清单
1. `sys_user_type` 用户类型表（角色表）
2. `sys_account` 系统账号表
3. `sys_permission` 权限资源表
4. `sys_type_permission` 用户类型权限关联表（角色权限）
5. `sys_account_permission` 账号独立权限关联表（单人自定义权限）

## 二、数据表详细结构
### 1. 用户类型表 `sys_user_type`

| 字段名 | 中文名称 | 数据类型 | 备注约束 | 字段说明 |
| ---- | ---- | ---- | ---- | ---- |
| type_id | 用户类型ID | BIGINT | 主键，自增 | 用户类型唯一标识；系统预置【超级管理员】固定记录 |
| type_name | 类型名称 | VARCHAR(64) | 唯一，非空 | 角色名称，如：超级管理员、保安、业务员，名称不可重复 |
| type_desc | 类型描述 | VARCHAR(256) | 可为空 | 用户类型备注说明 |
| create_time | 创建时间 | DATETIME | 非空 | 记录创建时间 |
| update_time | 更新时间 | DATETIME | 非空 | 记录更新时间 |

> **业务约束**
> 1. 系统初始化自动插入【超级管理员】记录；
> 2. 禁止物理删除超级管理员记录；
> 3. 超级管理员角色不支持配置权限。

### 2. 系统账号表 `sys_account`

| 字段名 | 中文名称 | 数据类型 | 备注约束 | 字段说明 |
| ---- | ---- | ---- | ---- | ---- |
| account_id | 账号ID | BIGINT | 主键，自增 | 账号唯一标识 |
| login_name | 登录账号 | VARCHAR(64) | 唯一，非空 | 用户登录用户名，全局唯一 |
| password | 登录密码 | VARCHAR(128) | 非空 | 加密存储密码 |
| real_name | 真实姓名 | VARCHAR(64) | 非空 | 用户真实姓名 |
| dept | 所属部门 | VARCHAR(64) | 可为空 | 部门信息 |
| phone | 联系方式 | VARCHAR(32) | 可为空 | 用户联系电话 |
| type_id | 用户类型ID | BIGINT | 非空，关联sys_user_type.type_id | 绑定所属用户类型 |
| status | 账号状态 | TINYINT(1) | 非空，默认1 | 1=启用；0=禁用账号 |
| create_time | 创建时间 | DATETIME | 非空 | 账号创建时间 |
| update_time | 更新时间 | DATETIME | 非空 | 账号信息更新时间 |
| last_login_time | 最后登录时间 | DATETIME | 可为空 | 用户最近一次登录时间 |

> **业务约束**
> 账号删除执行物理删除；账号禁用后无法登录系统。

### 3. 权限资源表 `sys_permission`

| 字段名 | 中文名称 | 数据类型 | 备注约束 | 字段说明 |
| ---- | ---- | ---- | ---- | ---- |
| perm_id | 权限ID | BIGINT | 主键，自增 | 权限唯一编号 |
| perm_name | 权限名称 | VARCHAR(128) | 非空 | 权限展示名称，例：摄像头查询、人员信息查询、账号新增 |
| perm_key | 权限标识 | VARCHAR(128) | 唯一，非空 | 程序鉴权编码，例：camera:query、person:query |
| perm_type | 权限类型 | TINYINT | 非空 | 1=菜单权限；2=按钮操作权限；3=数据查询权限 |
| parent_id | 父权限ID | BIGINT | 非空，默认0 | 构建权限树形结构，0代表顶级权限 |
| sort | 排序号 | INT | 默认0 | 前端权限树形展示排序 |
| create_time | 创建时间 | DATETIME | 非空 | 权限记录创建时间 |

### 4. 用户类型权限关联表 `sys_type_permission`

作用：统一配置某一类角色的默认权限

| 字段名 | 中文名称 | 数据类型 | 备注约束 | 字段说明 |
| ---- | ---- | ---- | ---- | ---- |
| id | 主键ID | BIGINT | 主键，自增 | 关联记录唯一ID |
| type_id | 用户类型ID | BIGINT | 非空，关联sys_user_type.type_id | 绑定目标用户类型 |
| perm_id | 权限ID | BIGINT | 非空，关联sys_permission.perm_id | 绑定权限资源 |

附加约束：增加联合唯一索引 `UNIQUE(type_id, perm_id)`，同一个类型不可重复绑定同一个权限

### 5. 账号独立权限关联表 `sys_account_permission`

作用：超级管理员针对单个账号自定义专属权限，优先级高于角色权限

| 字段名 | 中文名称 | 数据类型 | 备注约束 | 字段说明 |
| ---- | ---- | ---- | ---- | ---- |
| id | 主键ID | BIGINT | 主键，自增 | 关联记录唯一ID |
| account_id | 账号ID | BIGINT | 非空，关联sys_account.account_id | 目标账号ID |
| perm_id | 权限ID | BIGINT | 非空，关联sys_permission.perm_id | 绑定权限资源 |

附加约束：增加联合唯一索引 `UNIQUE(account_id, perm_id)`，同一个账号不可重复绑定同一个权限

## 三、核心权限判定规则
1. 若账号所属用户类型为【超级管理员】
   直接拥有系统全部权限，**不查询任何权限关联表**。
2. 普通账号权限加载顺序
   ① 查询 `sys_account_permission` 是否存在该账号自定义权限
   ✅ 存在：仅使用账号独立权限，**覆盖角色默认权限**
   ❌ 不存在：读取 `sys_type_permission`，继承所属用户类型权限

## 四、业务场景与表联动调用说明
### 场景1：系统初始化，创建内置超级管理员
1. 向 `sys_user_type` 插入初始数据：type_name = '超级管理员'
2. 在 `sys_account` 创建超级管理员账号，type_id绑定上述角色ID
3. 登录鉴权识别角色为超级管理员，直接放行全部功能，跳过权限表查询。

> 参与数据表：`sys_user_type`、`sys_account`

### 场景2：超级管理员新建【保安】用户类型并配置角色权限
需求：保安角色默认仅拥有摄像头查询、人员信息查询权限
1. `sys_user_type` 新增记录：类型名称=保安
2. 前端加载 `sys_permission` 获取完整权限树
3. 勾选目标权限，后台批量写入 `sys_type_permission`，建立保安角色与权限的关联

> 参与数据表：`sys_user_type`、`sys_permission`、`sys_type_permission`

### 场景3：新建账号【保安小张】，选择用户类型「保安」
1. `sys_account` 新增账号，type_id绑定保安类型ID
2. 未给小张配置独立权限
3. 小张登录权限加载流程：
    根据账号信息查询 `sys_account_permission` → 无数据
    转而查询 `sys_type_permission` 获取保安角色权限

> 参与数据表：`sys_account` → `sys_account_permission` → `sys_type_permission`

### 场景4：超级管理员单独给保安小张自定义专属权限
需求：小张不再沿用保安角色权限，单独分配摄像头查询、人员查询、账号列表权限
1. 在账号管理页面打开【自定义账号权限】，前端加载`sys_permission`权限树
2. 保存配置，后台清空小张原有`sys_account_permission`记录，插入新权限关联
3. 小张登录鉴权：查询到`sys_account_permission`存在数据，直接使用单人权限，忽略保安角色权限

> 参与数据表：`sys_permission`、`sys_account_permission`

### 场景5：取消小张独立权限，恢复角色默认权限
1. 权限设置切换为【使用角色默认权限】
2. 物理删除小张所有`sys_account_permission`相关记录
3. 下次登录自动读取保安角色在`sys_type_permission`中的权限

> 参与数据表：`sys_account_permission`、`sys_type_permission`

### 场景6：修改【保安】角色默认权限
管理员移除保安角色的人员查询权限
1. 编辑保安角色权限，删除`sys_type_permission`内对应type_id全部记录，重新插入新权限关联
2. 生效区分：
    ✅ 无独立自定义权限的保安账号：权限同步更新
    ❌ 配置过独立权限的账号（小张）：不受影响，继续使用单人权限

> 参与数据表：`sys_type_permission`

### 场景7：删除用户类型【保安】
前置校验逻辑：
1. 查询`sys_account`，判断是否存在账号type_id关联保安；存在账号引用 → 禁止删除
2. 无账号引用时：
    ① 删除`sys_type_permission`中保安角色所有权限关联记录
    ② 删除`sys_user_type`保安类型记录

> 参与数据表：`sys_account`、`sys_type_permission`、`sys_user_type`

### 场景8：账号离职，物理删除保安小张账号
1. 删除`sys_account`中小张账号记录
2. 级联物理删除`sys_account_permission`中属于小张的所有独立权限记录

> 参与数据表：`sys_account`、`sys_account_permission`

### 场景9：用户登录通用鉴权完整链路
1. 用户输入账号密码登录，查询`sys_account`校验账号名称、密码、账号状态status
2. 获取账号type_id，查询对应用户类型名称
3. 如果是超级管理员，直接授予全部权限；
4. 如果是普通角色：
    第一步：查询`sys_account_permission where account_id = 当前账号ID`
    - 查到数据：使用账号独立权限集合
    - 无数据：查询`sys_type_permission where type_id = 角色ID`，使用角色权限集合
5. 缓存权限标识集合，后续所有接口请求执行权限校验

## 五、表关系简图
```
sys_account（账号）
        ↓ type_id关联
sys_user_type（角色）
        ↘️ 无单人权限时 → sys_type_permission（角色权限）
账号account_id → sys_account_permission（单人权限，优先生效）
                        ↓
                sys_permission（全部权限资源定义）
```
