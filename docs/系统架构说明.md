# 前后端分离单体 API 系统架构说明

## 1. 文档目的

本文档描述本项目的基础系统架构、目录边界、运行依赖、部署关系和后续扩展约束。本次交付仅搭建架构，不实现具体业务流程、业务数据模型、业务接口或业务页面。

需求调研材料涉及智慧城市、公共安全视频图像信息系统、视频感知和异常行为等方向。因此，本架构保留了后续接入设备、视频分析、事件告警、权限管理、报表和文件处理等领域模块的扩展位置，但不在当前骨架中预置任何业务实现。

## 2. 架构定位

采用“前后端分离 + Python 单体 API”的中小型项目首选架构：

- 前端独立构建和发布，通过 HTTP/HTTPS 调用后端 REST API。
- 后端以一个 FastAPI 服务承载全部业务接口。
- 后端内部采用 API/Controller、Service、Repository/DAO、Model 四层分离。
- MySQL 负责持久化数据，Redis 负责缓存、会话、限流和异步任务消息。
- Nginx 作为统一入口，负责反向代理和后续静态资源、TLS、压缩等能力。
- Celery 作为可选异步任务执行器，处理耗时或非实时任务。

## 4. 技术选型

| 层次 | 技术 | 责任 |
|---|---|---|
| 接入层 | Nginx | 统一域名、反向代理、TLS 终止、静态资源入口 |
| 前端 | Vue 3、Vite、TypeScript | 页面展示、路由、状态管理、API 调用 |
| API 层 | FastAPI、Uvicorn | 路由、参数校验、鉴权入口、响应编排 |
| 服务层 | Python Service | 用例编排、事务边界、领域规则 |
| 数据访问层 | SQLAlchemy Async | 数据库访问、查询封装、仓储实现 |
| 数据库 | MySQL 8.4 | 结构化业务数据持久化 |
| 缓存/消息 | Redis 7.4 | 会话、热点数据、限流、Celery Broker/Backend |
| 异步任务 | Celery | 邮件、文件处理、定时任务、报表生成等耗时任务 |

## 6. 后端分层约束

### 6.1 API / Controller 层

负责接收 HTTP 请求、校验输入、注入依赖、调用 Service、转换统一响应。禁止在路由函数中直接编写 SQL 或复杂业务判断。

### 6.2 Service 层

负责承载业务用例、组合多个 Repository、控制事务边界和处理领域规则。Service 不依赖具体 HTTP 对象，便于测试和未来接入异步任务或其他调用端。

### 6.3 Repository / DAO 层

负责封装 SQLAlchemy 查询和持久化细节。上层通过 Repository 访问数据，不直接依赖表结构或 SQL 细节。

### 6.4 Model 层

负责数据库实体和关系映射。请求/响应对象使用 `schemas` 中的 DTO，不直接把 ORM Model 暴露给前端。

## 7. 数据与缓存边界

- MySQL：保存需要可靠持久化的数据；数据库连接通过环境变量配置。
- Redis：保存短生命周期数据，包括登录会话、热点查询结果、接口限流计数和 Celery 消息。
- 缓存必须设置过期时间，并明确缓存键命名空间；业务真相始终以 MySQL 为准。
- 文件或视频类大对象不建议直接存入 MySQL，应预留对象存储或文件服务适配层。
- 数据库迁移工具可在首个业务模块落地时补充 Alembic，当前不生成业务迁移文件。

## 8. 异步任务扩展

Celery 通过 Redis 作为 Broker 和结果后端。适合以下任务：

- 邮件、短信或通知发送
- 视频、图片和文件处理
- 定时清理和数据同步
- 报表生成和导出
- 非实时分析任务

API 请求只负责创建任务并返回任务标识；Worker 负责执行，前端通过查询接口或推送机制获取状态。实时接口不应等待长耗时任务完成。

## 9. 接口与版本策略

- API 前缀统一为 `/api/v1`。
- 健康检查提供 `/health` 和 `/api/v1/system/health`，用于容器和负载均衡探活。
- 后续接口按领域拆分到 `api/v1/endpoints`，版本升级时新增 `v2`，避免直接破坏旧客户端。
- 响应结构、错误码、分页和鉴权约定应在首个业务模块开发前统一定义。

## 10. 部署策略

开发环境可使用 `docker compose` 启动后端、前端、Nginx、MySQL 和 Redis。生产环境建议：

1. 前端执行构建，将静态资源交给 Nginx 或 CDN。
2. 后端使用多进程 Uvicorn/Gunicorn 或容器副本部署。
3. Nginx 仅暴露公网端口，后端、数据库和 Redis 使用内网通信。
4. MySQL 与 Redis 使用独立持久化卷和备份策略。
5. Celery Worker 与 API 服务分开扩容。
6. 通过环境变量或密钥管理服务注入敏感配置，不提交真实密码。

## 11. 安全与运维预留

- 生产环境启用 HTTPS，并限制 CORS 来源。
- 鉴权中间件、权限依赖、操作审计和敏感数据脱敏应放在后端公共层。
- Nginx 和 API 层均应设置请求体大小、超时和限流策略。
- 日志输出请求追踪标识、状态码和耗时，不输出密码、令牌和敏感视频信息。
- 健康检查与业务可用性检查分离，避免数据库短暂异常导致容器无法诊断。

## 12. 当前交付范围

已提供：

- FastAPI 单体 API 的分层目录和最小启动入口
- Vue 3 + Vite 前端工程入口和路由预留
- MySQL、Redis、Nginx、Celery 的配置接入位置
- Docker Compose 编排骨架
- 系统架构说明文档
- 仅用于探活的健康检查接口

未提供：

- 任何业务实体、业务接口和业务页面
- 登录、权限、菜单、告警、视频、报表等实际功能
